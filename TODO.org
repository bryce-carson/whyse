** Carbon copies of the tool syntax
When conducting business on paper using a (carbon) copy pad is commonplace to
produce a copy of a document---such as a form or a receipt---for both customer
and business records. =carboncopy= is such a filter, which copies the tool
syntax it receives to a file named in the shell variable =CARBONCOPY= and then
passes its input to its output.

It is a wrapper around the command =tee=, ensuring =CARBONCOPY= is set and
non-null and that noclobber is not set.

#+begin_src bash :tangle carboncopy :shebang #!/usr/bin/env bash
  if [[ -n ${CARBONCOPY:?"shell variable is unset or null!"} && !$(echo $SHELLOPTS | grep noclobber) ]]; then {
      tee </dev/stdin $CARBONCOPY
  }
  fi;
#+end_src

* The stages in the /notangle/ pipeline
The wrapper script =notangle= has hardcoded paths to =markup= and the LIBEXEC of
Noweb. The wrapper parses the arguments and constructs the pipeline.

1. Convert the web to a machine-readable (tool) format using =markup=.
2. Extract the desired code chunk with =/usr/libexec/noweb/nt=.

=nt= therefore depends upon =markup=.

#+name: notangle
#+begin_src shell
  #!/usr/bin/sh
  # Copyright 1991 by Norman Ramsey.  All rights reserved.
  # See file COPYRIGHT for more information.
  LIB=/usr/libexec/noweb
  markup=$LIB/markup opt= arg= markopt= filters=
  while [ $# -gt 0 ]; do
          case $1 in
          -gitversion) echo "50840b12b87af91fe9aea6b4979ea7f71286b5be" ; exit ;;
          -ml|-m3|-awk|-icn|-icon|-pascal|-c|-c++|-f77|-f90|-tex|-w[0-9][0-9]*) ;; 
                                          # deliberately ignore nountangle args
          -t)  ;; # this is default
          -t*) markopt="$markopt -t" ; opt="$opt '$1'" ;;
                  # copy tabs at markup, use width given in notangle
          -filter) filters="$filters $2 | " ; shift ;;
          -markup) markup="$2" ; shift ;;
          -)   arg="$arg '$1'" ;;
          -L*) opt="$opt -t '$1'" ; markopt="$markopt -t" ;;
          -*)  opt="$opt '$1'" ;;
          ,*)   arg="$arg '$1'" ;;
          esac
          shift
  done
  PATH="$PATH:$LIB" 
  export PATH
  eval "$markup $markopt $arg | $filters $LIB/nt $opt "'; rc=$?'
  exit $rc
#+end_src

This is an example of a particular noweave pipeline which includes indexing C

* The stages in the /whyse/ pipeline
This is hypothetical.

#+begin_src sh :var WEB="~/src/whyse/src/whyse.nw"
  markup WEB | autdefs elisp | finduses -noquote | noidx
#+end_src

1. Convert the web to a machine-readable (tool) format: ~markup WEB~.
2. Identify definitions of identifiers: ~autodefs elisp~.
3. Find usages of identifiers, skipping uses in quoted code (documentation): ~finduses -noquote~.
4. Create an index of identifiers and cross-references: ~noidx~.
5. Generate Emacs LISP.
   1. Convert code and documentation chunks into widgets.
      1. Documentation chunks are largely preserved as plain text; quotations and cross-references may need special handling.
      2. Code chunks are converted to widgets using plain text.
6. Evaluate the Emacs LISP.
7. Modify the web source buffer using whyse-mode.
8. Export the buffer to a web.
   1. Convert widgets to plain text.
      1. Chunk definition widgets contain "<<chunk-name>>=", which can be written directly; the rest of the widget data isn't exported.
      2. Documentation chunks are already plain text.
   2. Save the buffer to a file.
9. Repeat steps 1--8 until the program and its documentation is complete.

fairly easy to understand that these must be paired properly. Exactly
what they do is not a concern to me yet, I'm just noting that these are
here and that they're mirrored commands. BEGIN. END. Simple, right?

=moddef= and =endmoddef= are likewise paired commands. (IMPLICITLY
BEGIN)THING. ENDTHING. This is less simple.
